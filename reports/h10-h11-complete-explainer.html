Как работают H10 и H11

От обычного текстового утверждения до ответа «истина», «ложь» или «неизвестно». Без скрытых ступеней, внутренних названий прошлых опытов и необъяснённых сокращений.

Как читать названия

H10 — исследовательское имя структурного поиска фактов. H11 — исследовательское имя всей двухступенчатой схемы, которая запускает структурный поиск только после ответа «неизвестно». Дальше эти механизмы названы по смыслу.

Суть за минуту

Это два разных уровня

Первый механизм умеет находить связную цепочку фактов в графе знаний. Второй решает, когда вообще стоит тратить время на этот механизм.

H10 · структурный поиск

Ищет не похожие факты по отдельности, а связный путь

Он превращает утверждение в маленький граф, связывает его вершины с объектами графа знаний, восстанавливает пропущенные конечные вершины и ищет путь из одного или двух рёбер, который выражает нужную связь.

Результат: компактный набор реальных троек графа знаний.

H11 · условный запуск

Сначала использует простой широкий поиск

Если первая проверка уверенно отвечает «истина» или «ложь», ответ сразу сохраняется. Структурный поиск запускается только после «неизвестно» и получает шанс найти более связное основание.

Результат: меньше лишних вычислений и сохранение уже данных уверенных ответов.

В одной строке: сначала быстро собираем до двадцати похожих фактов; если их недостаточно, строим небольшой графовый аргумент и спрашиваем модель ещё раз.

Весь путь

От текста до окончательного ответа

Оранжевая развилка — единственное место, где двухступенчатая схема решает, нужен ли дорогой структурный поиск.

1Текст утверждения

Например: «Продюсер фильма родился в Санкт-Петербурге».

2Извлечение структуры

Языковая модель строит небольшой граф утверждения.

3Широкий поиск

Из локальной области графа знаний выбираются до 20 текстово близких фактов.

4Первая проверка

Модель отвечает только по найденным фактам.

5Ответ «неизвестно»?

Нет — остановка. Да — запускается структурный поиск.

6Связный аргумент

Новый компактный набор фактов снова проверяется моделью.

H10 подробно

Как строится связный аргумент

Ниже описана фактически выбранная упрощённая версия: одна новая конечная вершина на вершину утверждения, пути длины один–два, без отдельного штрафа за нового кандидата.

Построить граф смысла утверждения

Языковая модель извлекает явно сказанные сущности и отношения. Она обязана использовать названия из исходной фразы. Неизвестная сущность обозначается вопросительным знаком.

Упрощённый Python: представление графа утверждения 
# Это не запрос к базе. Это структура смысла фразы.
graph = {
    "vertices": ["film", "?", "Saint Petersburg"],
    "edges": [
        ("film", "producer", "?"),
        ("?", "born in", "Saint Petersburg"),
    ],
}

Найти исходные соответствия по именам

Для каждой известной вершины ищутся объекты графа знаний с таким же или близким названием. Проверяются прямые варианты идентификатора и полнотекстовый индекс. Для одной вершины сохраняется не более пяти исходных вариантов.

От найденных объектов строится локальная область глубины два. На каждом шаге берутся до тридцати фактов, наиболее близких к тексту утверждения; общий предел — две тысячи троек.

Зачем локальная область? Полный граф знаний слишком велик. Два перехода дают материал для короткой цепочки, но не позволяют поиску бесконтрольно уйти далеко от известных сущностей.

Предложить пропущенную конечную вершину

Главная добавка алгоритма: если один конец ребра уже связан с объектом графа знаний, от него перебираются направленные пути длины один или два. Конец каждого пути становится возможным соответствием соседней вершины утверждения.

Упрощённый Python: как появляются предложения 
for edge in statement_graph.edges:
    for known_object in candidates[edge.source]:
        for path in paths_from(known_object, max_length=2):
            proposed_object = path[-1].target
            remember_proposal(
                vertex=edge.target,
                object=proposed_object,
                path=path,
            )

Оценить каждое предложение

Алгоритм проверяет две вещи: похожи ли отношения в найденном пути на отношение из утверждения и похоже ли имя конечного объекта на название вершины. Двухрёберный путь получает небольшой штраф, чтобы прямое ребро побеждало при равном качестве.

оценка = 0,7 × сходство отношений + 0,3 × сходство названий − 0,1 × (длина пути − 1)

Сходство отношений вычисляет замороженная небольшая языковая модель: она превращает текст отношения в числовой вектор, после чего сравнивается направление этих векторов. Генерирующая модель здесь не вызывается.

Упрощённый Python: формула предложения 
def proposal_score(relation_similarity, name_similarity, path_length):
    length_penalty = 0.1 * (path_length - 1)
    return (
        0.7 * relation_similarity
        + 0.3 * name_similarity
        - length_penalty
    )

Оставить только одно лучшее новое соответствие

Для каждой вершины утверждения варианты сортируются по оценке. К исходным соответствиям добавляется только один лучший новый объект. Это выбранная после разборки компонентов версия алгоритма.

Что было удалено как лишнее: второй новый объект на вершину и отдельный штраф за использование нового объекта. Их удаление не ухудшило качество на проверочных наборах.

Собрать полное соответствие графов

Теперь выбирается не лучший путь для каждого ребра отдельно, а одно общее соответствие для всех вершин утверждения. Один объект графа знаний нельзя назначить двум разным вершинам. Сопоставлено должно быть не менее 80% вершин.

Все комбинации перебирать слишком дорого. Поэтому после добавления очередной вершины сохраняются только 64 лучших частичных варианта. Это ограниченный поиск: он быстрый, но не обещает математически найти абсолютный мировой минимум.

общая стоимость = 0,3 × ошибка вершин + 0,7 × ошибка рёбер

Для каждого ребра утверждения разрешён путь графа знаний длины один или два. Ошибка ребра равна единице минус смысловое сходство лучшего пути. Двухрёберный путь снова получает штраф 0,1.

Упрощённый Python: ограниченный совместный поиск 
partial_mappings = [{}]

for vertex in ordered_vertices:
    expanded = []
    for mapping in partial_mappings:
        for object_id in candidates[vertex]:
            if object_id in mapping.values():
                continue  # один объект нельзя использовать дважды
            new_mapping = mapping | {vertex: object_id}
            expanded.append((cost(new_mapping), new_mapping))

    partial_mappings = take_best(expanded, count=64)

best_mapping = minimum_cost(partial_mappings)

Вернуть только реальные факты выбранных путей

Алгоритм ничего не дописывает от себя. Он берёт рёбра тех путей, которые победили, удаляет повторы и возвращает не более двадцати исходных троек графа знаний.

После этого языковая модель видит утверждение и только эти факты. Ей разрешено ответить «истина», «ложь» или «неизвестно». Отсутствие факта не считается доказательством ложности.

Первая проверка не может сделать вывод

Модель обязана использовать только переданные факты. В них нет явного места рождения найденного продюсера.

Вторая проверка получает короткое достаточное основание

Обе тройки образуют одну цепочку, а промежуточная вершина — один и тот же человек.

H11 подробно

Когда запускается структурный поиск

Это простое условие вокруг двух способов поиска. Оно использует только наблюдаемый ответ модели, а не правильную метку из набора данных.

Первая проверка дала «истина» или «ложь»

Ответ сохраняется без изменений. Структурный поиск и второй вызов языковой модели не выполняются.

НЕИЗВЕСТНО?

Первая проверка дала «неизвестно»

Запускается структурный поиск, его компактные факты передаются той же модели. Новый ответ заменяет только «неизвестно».

Почему схема не теряет уже правильные первые ответы: она вообще не имеет права менять «истина» или «ложь». Но это не значит, что первая проверка никогда не ошибается — её ошибочный уверенный ответ также будет сохранён.
Что делает модель

Языковая модель используется в трёх разных ролях

Важно не смешивать извлечение структуры, численное сравнение отношений и окончательную проверку.

Извлечение графаБольшая языковая модель один раз переводит утверждение в вершины и рёбра. Невалидный ответ можно повторить с большим пределом длины.
Сравнение связейНебольшая замороженная модель вычисляет числовое сходство текстов. Она не генерирует факты и не отвечает на вопрос.
Проверка утвержденияБольшая языковая модель видит только утверждение и выбранные реальные тройки, после чего возвращает один из трёх ответов.

Честные границы

Что мы знаем и чего не знаем

Подтверждено

  • Восстановление конечной вершины и поиск пути дают пользу сверх плоского выбора тех же двухшаговых фактов.
  • Условный запуск после «неизвестно» улучшил широкий поиск на независимой проверочной и фиксированной тестовой выборках FactKG.
  • Второй новый кандидат и отдельный штраф нового кандидата можно удалить без потери качества.
  • Структурный поиск не требует дополнительных вызовов большой модели до этапа проверки ответа.

Не подтверждено

  • Польза единого глобального соответствия всех вершин: независимый выбор пути для каждого ребра оказался почти таким же.
  • Превосходство над опубликованными системами при одинаковом наборе данных и протоколе.
  • Перенос результата на обычные вопросы: на HotpotQA графовый поиск улучшил поиск опорных предложений, но не дал значимого роста качества ответа.
  • Что любой уверенный первый ответ правильный: условие защищает его от замены, но не исправляет уверенные ошибки.
Самопроверка

Если вы поняли эти четыре пункта — алгоритм понятен

Структурный поиск

Начинает с известных объектов, проходит по реальным рёбрам на один–два шага, предлагает пропущенные конечные вершины и выбирает компактный связный набор фактов.

Условная схема

Не объединяет два списка фактов. Она делает вторую независимую попытку только тогда, когда первая попытка честно отказалась отвечать.

Никаких придуманных рёбер

Смысловое сходство используется только для выбора. В окончательное основание попадают реальные тройки из графа знаний.

Главный практический эффект

Широкий поиск хорошо работает в большинстве случаев; связный путь нужен для трудного меньшинства, где отдельные похожие факты не складываются в вывод.
