Мягкое сопоставление графа текста с графом знаний

Цель — проверить, можно ли устойчиво сопоставлять граф отношений, извлечённый из claim, с DBpedia при неточных именах, отношениях и топологии. Пройдена серия из восьми зафиксированных гипотез. Лучший текущий результат — H10: path-guided endpoint linking вместе с edge-to-path soft matching.

Краткий вывод

Что доказано: H8 устойчиво улучшает базовый soft matcher B4; H10 на диагностических 500 claims существенно улучшает retrieval относительно H9.

Что не доказано: пока нет результата reader для H10, независимого подтверждения на ranks 1000–1499 и test. Нельзя утверждать, что H10 улучшает Accuracy или превосходит SimGRAG/B1.

Постановка и данные

Основная задача

FactKG fact verification: по claim и только найденным KG-фактам вернуть TRUE, FALSE или UNKNOWN. UNKNOWN считается ошибкой в Accuracy.

Данные

FactKG: 86 367 train, 13 266 dev, 9 041 test. KG — DBpedia 2015 light; индекс имён охватывает 9 913 189 сущностей. Gold label и Evidence не передаются retrieval.

Бенчмарки

FactKG — основной. HotpotQA distractor выбран как второй для проверки переноса, но графовые H8–H10 на нём ещё не запускались.

Аналоги

SimGRAG — ближайшая референсная работа по query-graph retrieval и FactKG. NGM-RAG — соседняя GNN-работа и ориентир для HotpotQA; её framework локально не воспроизводился.

Нумерация экспериментов историческая: ранние гипотезы назывались E1 и E4, затем H5–H10. B0–B4 — baseline-методы, а не пропущенные гипотезы H2/H3.

Общий экспериментальный pipeline

01 · CLAIMFactKG textМетка скрыта от retrieval.
02 · EXTRACTIONQuery graphQwen3.8-27B, один вызов на claim.
03 · LINKINGEntity domainsКандидаты DBpedia и общий KG pool.
04 · MATCHINGSoft mappingУзлы, рёбра или пути; beam width 64.
05 · READERTRUE/FALSE/UNKNOWNОдинаковый KG-only prompt для arms.

C(f) = 0.3 · mean(node distance) + 0.7 · mean(edge/path distance)

Primary end-to-end метрика — Accuracy; вторичные — Macro-F1 и UNKNOWN. Retrieval диагностируется через path-constraint coverage: долю авторских FactKG paths, присутствующих в evidence.

Все проверенные гипотезы

E1

Agreement-weighted edges. Вес ребра из согласия нескольких LLM-extractions должен снижать влияние ненадёжных связей.

В однопроходном режиме все веса равны 1, поэтому E1 точно тождественен B3. В старом dev-20 mapping/evidence совпали 20/20; Accuracy 3/20, UNKNOWN 17/20.

отклонена
E4

Path-consistency penalty. Штраф 0,2 за незавершённые query paths длины 2–3 должен выбирать более структурно согласованные mappings.

На dev-20 и test-20 штраф постоянен внутри top-50: 0 изменений mapping/evidence. Dev Accuracy B4/E4 5%/5%, UNKNOWN 19/19; test 0%/0%, UNKNOWN 20/20.

не прошла gate
H5

Connected residual paths. Дополнять первые 12 B1-троек связными путями длины 2–3 до бюджета 20.

Coverage вырос с 19/32 до 22/32, но Flat-контроль восстановил те же пути. Вклад именно связности не показан. Exploratory reader: 10/20 Accuracy, 7 UNKNOWN.

механизм не выделен
H6

Flat semantic expansion. Заменить слабый хвост B1 независимо отобранными по cosine тройками.

При coverage 22/32 против 19/32 у B1, Accuracy снизилась 60%→55%, UNKNOWN вырос 6→7. Один правильный FALSE стал UNKNOWN.

отклонена
H7

Contextual edge cost + domain expansion. Сравнивать полные query/KG edges и добавлять relation-guided соседей в domains.

На dev-20: B4 8/32, contextual cost C7 18/32, полная H7 16/32. Expansion изменила 15/20 mappings, но не добавила ни одного path сверх C7 и потеряла два.

расширение отклонено
H8

Contextual full-edge cost. Оставить исходные domains, но заменить relation-only distance на cosine между полными рёбрами source–relation–target.

Независимые 50: B4→H8 Accuracy 2%→8%, UNKNOWN 49→46, coverage 4/57→14/57. Cumulative 100: Accuracy 2%→16%, UNKNOWN 98→83, coverage 8/134→35/134; H8-only correct 14, B4-only 0, p=0,000122.

пилот поддержан
H9

Edge-to-path matching. Разрешить одному query edge сопоставляться с направленным KG-путём длины 1–2 с штрафом 0,1 за hop.

На 500 diagnostic claims coverage 219/767→239/767 (+2,61 п.п.), evidence 178→245; найдено 8 двухшаговых gold paths. Прирост ниже зафиксированного gate +5 п.п.

механизм работает, gate нет
H10

Path-guided endpoint linking. К H9 добавить не более двух endpoint-кандидатов на query node, найденных по путям; добавить provenance penalty 0,15.

На тех же 500 diagnostic claims coverage 239/767→321/767 (+10,69 п.п.), length-2 8→28, evidence 245→481. H10-only/H9-only paths 85/3; p=7,34e−22. Все retrieval gates пройдены.

retrieval поддержан

Идея текущего подхода H10

1. Исходные якоря

Для конца query edge берутся entity candidates из обычного linking.

→

2. Path-guided proposals

От якоря ищутся пути длины 1–2. На query node добавляются не более двух endpoints.

→

3. Joint soft matching

Beam search выбирает mapping и KG edge/path; расширенный endpoint получает штраф 0,15.

proposal = 0.7 · cosine(query relation, relation sequence) + 0.3 · label similarity − 0.1 · extra hop

Почему не H7

H7 добавляла до пяти соседей на edge в два раунда и не штрафовала их происхождение. H10 ограничивает expansion двумя кандидатами на node и использует provenance penalty.

Пример

Query edge film — producer is from → city может быть сопоставлен с KG-путём film — producer → person — birthPlace → city. H9 умела оценить такой путь, только если оба конца уже были в domains; H10 может добавить пропущенный конец.

Границы вывода

Diagnostic ≠ confirmation

H9 и H10 выведены из анализа ranks 500–999, поэтому их цифры на этих 500 claims — диагностика механизма. Независимый диапазон ещё не запущен.

Retrieval ≠ Accuracy

Высокое gold-path coverage не гарантирует правильный verdict. H6 уже показала, что retrieval может вырасти, а Accuracy — снизиться.

Нет прямой победы над SimGRAG

В текущей среде не воспроизведён авторский SimGRAG с теми же KG, sample IDs, model и budget. Paper numbers можно приводить только как внешний ориентир.

Внешний блокер

iairlab/qwen3.8-27b через ITMO LiteLLM возвращает HTTP 500 model group connection error. Из-за этого не завершены H10 reader и extraction новых claims.

Что делать дальше

1. End-to-end gate

Один reader оценивает H9/H10 на текущих 500. Gate зафиксирован до результата: H10 должен дать ≥+5 п.п. Accuracy, меньше UNKNOWN, Macro-F1 не хуже более чем на 1 п.п. и paired p<0,05.

2. Independent dev

Только при прохождении reader-gate извлечь графы для FactKG dev SHA-ranks 1000–1499 и повторить замороженные H9/H10 без изменения параметров.

3. Test и второй benchmark

При подтверждении на independent dev — зафиксировать test subset, сравнить с B1/B0 и после этого проверять перенос на HotpotQA.
