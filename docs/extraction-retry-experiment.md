# Extraction retry: восстановление обрезанных query graphs

Дата фиксации дизайна: 22.11.2026, до получения повторных extraction
responses.

## Наблюдение

На FactKG dev SHA-256 ranks 1500–1999 первичный extraction с одним
open-relation view и лимитом 256 output-токенов дал 122/500 пустых query
graphs. Проверка сохранённых raw responses показала:

- 107 ответов завершились с `finish_reason=length` и 256 completion tokens;
- 15 ответов завершились с `stop`, но не прошли строгую проверку JSON,
  schema, grounded node labels или exact-substring quotes;
- все 378 непустых графов завершились с `stop`.

Это post-hoc engineering diagnostic на уже использованном срезе, а не новая
confirmatory оценка качества метода.

## Замороженный алгоритм retry

1. Скопировать все строки первичного extraction в новый артефакт.
2. Строки с `valid_views > 0` не отправлять модели и не изменять.
3. Только для строк с `valid_views == 0` повторить тот же extraction prompt,
   model, temperature, seed, JSON mode и open-relation setting.
4. Единственное изменение — увеличить `max_tokens` с 256 до 512.
5. Повторный ответ проходит ту же функцию `parse_view`; ослаблять grounding,
   exact quotes или schema validation запрещено.
6. При невалидном retry сохранить пустой граф и явную причину ошибки.

## Метрики и правило результата

- recovered valid/non-empty graphs из 122 retries;
- отдельно recovery для 107 `length` и 15 `stop` случаев;
- число Qwen calls, tokens и model time;
- SHA-256/точное равенство 378 строк, не требовавших retry;
- после downstream rerun: B1 UNKNOWN rate, Accuracy и полный frozen
  H10-lean result.

Диагностическая гипотеза считается поддержанной, если восстановлено не менее
90/122 query graphs, а все 378 исходно валидных строк остались неизменными.
Это доказывает только механическую пользу adaptive output budget. Любой
вывод о качестве на данных требует отдельной свежей выборки.

## Диагностический результат

Retry с лимитом 512 завершён на всех 122 строках:

- восстановлено **100/122** query graphs, порог 90 выполнен;
- среди 107 исходных `finish_reason=length` восстановлено **99**, не
  восстановлено 8;
- среди 15 исходных завершённых, но невалидных ответов восстановлен 1;
- все **378/378** исходно валидных строк остались точно неизменными;
- выполнено 122 Qwen-вызова, использовано 58 380 токенов и 580,54 с
  суммарного model time;
- после retry 121 ответ завершился с `stop`, один снова достиг лимита;
- из оставшихся 22 ошибок 19 связаны с не дословной `quote`, 2 — с
  невалидными endpoint IDs, 1 — с невалидным JSON.

Диагностическая гипотеза поддержана: adaptive budget устраняет 92,5%
случаев обрезки (99/107), не затрагивая валидные результаты. Смягчать
валидацию для оставшихся 22 случаев нельзя без отдельного дизайна, так как
это меняет гарантию grounded extraction.

## Downstream результат с замороженным matcher

Для 100 восстановленных графов заново построены candidate pools; 400
неизменившихся строк переиспользованы только при точном совпадении текста и
графа. Затем повторены B1 и H10-lean без изменения их параметров.

| Pipeline | Accuracy | Macro-F1 | UNKNOWN | Fallback rate |
|---|---:|---:|---:|---:|
| До retry: B1 | 45,8% | 0,5957 | 234 | 46,8% |
| После retry: B1 | 58,2% | 0,6869 | 158 | 31,6% |
| После retry: B1 → H10-lean | **64,2%** | **0,7217** | **116** | 31,6% |

Extraction retry добавил B1 62 правильных ответа (+12,4 п.п.) без потери
ранее правильных ответов. Операционный gate `fallback rate ≤ 40%` теперь
выполнен. Замороженный H10-lean добавил ещё 30 правильных ответов (+6,0
п.п.; method-only 30, B1-only 0, exact paired p=1,86×10⁻⁹) и снизил UNKNOWN
с 158 до 116.

Добавочная стоимость downstream пересчёта:

- 100 новых B1 reader calls: 69 055 токенов, 50,44 с model time;
- H10-lean retrieval для 158 B1 UNKNOWN: 21,71 с wall time;
- 24 новых lean reader calls с изменившимся evidence: 3 848 токенов,
  14,14 с model time;
- построение 100 новых pools: 226,01 с wall, 212,09 с CPU, peak RSS около
  11,34 ГБ.

Итоговая инженерная рекомендация: использовать adaptive extraction budget
как механическую защиту от обрезки, затем B1 и только после его UNKNOWN —
H10-lean. Числа 58,2%/64,2% являются post-hoc диагностикой на том же срезе;
полный pipeline надо один раз проверить на новой неиспользованной выборке.
