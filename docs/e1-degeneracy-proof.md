# Доказательство вырождения E1 при равных весах рёбер

## Точное утверждение

Для фиксированных графа утверждения, KG, набора кандидатов и параметров
поиска, если все рёбра графа утверждения имеют одинаковый положительный вес
`c`, реализованные E1 и B3 возвращают одинаковые стоимости каждого mapping,
порядок поиска, выбранный mapping и evidence. В пилотном pipeline они
передают reader одинаковый prompt и получают одинаковый verdict благодаря
общему кэшу одинаковых запросов. Поэтому разница Accuracy E1−B3 на любой
выборке из таких графов **строго равна нулю**. Время выполнения не обязано
совпадать.

## Доказательство

Для любого допустимого отображения `f` обозначим через `D(f)` среднюю
стоимость узлов, а через `d_e(f)` стоимость ребра `e` в диапазоне `[0,1]`.
В [реализации](../src/soft_isomorphism/matching.py) обе ветви вычисляют

```text
C(f) = 0.3 · D(f) + 0.7 · (Σ_e c_e d_e(f)) / (Σ_e c_e).
```

B3 подставляет `c_e=1`; E1 подставляет сохранённую `confidence`.
Если для всех рёбер `c_e=c>0`, то

```text
(Σ_e c d_e(f)) / (Σ_e c) = (Σ_e d_e(f)) / |E|.
```

Следовательно, `C_E1(f)=C_B3(f)` **для каждого** допустимого `f`, а не
только для победителя. Та же подстановка действует в нижней оценке частичного
mapping в [beam search](../src/soft_isomorphism/search.py), поэтому при
одинаковых candidate pool, бюджете и детерминированном порядке разрешения
ничьих поиск проходит одинаково. В [пилоте](../scripts/factkg_e1_pilot.py)
candidate pool общий, а при равных весах сортировка рёбер для evidence
сохраняет исходный порядок в обеих ветвях. `expanded_evidence` зависит от
mapping и KG, но не от веса. Reader кэширует запрос по `claim + evidence`;
одинаковые входы используют один и тот же ответ модели. Пустой граф
обрабатывается одинаково обеими ветвями.

При **одном** извлечении `merge_views` считает каждое уникальное ребро
встретившимся в 1 из 1 view, поэтому `confidence=1` у каждого ребра.
Следовательно, теорема охватывает все утверждения текущего однопроходного
пилота независимо от их содержания и качества KG.

## Проверка сохранённых результатов

На первых 20 FactKG dev и первых 20 test claims однопроходного пилота:

| Проверка | dev | test |
|---|---:|---:|
| Все веса рёбер равны 1 | 20/20 | 20/20 |
| Совпадают status, mapping и evidence B3/E1 | 20/20 | 20/20 |
| Совпадает verdict B3/E1 | 20/20 | 20/20 |

Для dev использованы сохранённые до последующей правки linking файлы
`match-link-v1.jsonl` и `predictions-link-v1.jsonl`; для test — `match.jsonl`
и `predictions.jsonl`. Они находятся в игнорируемом Git каталоге
`data/evaluation/e1-pilot-itmo-qwen3_8-27b-open-{dev,test-20}/`.
Эта проверка подтверждает работу реализации на 40 claims; всеобщий вывод
следует из формулы выше.

## Почему старый трёхпроходный пилот не даёт всеобщего опровержения

В сохранённом FactKG dev-20 прогоне с тремя извлечениями 36 из 46 рёбер
получили вес меньше 1, но **только 7 из 20 графов имели неодинаковые веса
между своими рёбрами**. Для остальных 13 графов теорема снова гарантирует
тождество B3/E1, даже если общий вес меньше 1. В версии
`match-bm25-v2.jsonl` различий mapping и evidence не было ни на одном из
20 claims; Accuracy обоих методов — 3/20, UNKNOWN — 17/20. Таким образом,
только 7 claims этого малого dev-пилота вообще могли показать эффект весов;
они его не показали.

Неодинаковые веса **могут** изменить решение. Например, граф с узлами `a,c`
и двумя требованиями `a-r1-c`, `a-r2-c` сопоставляется с KG, содержащим
`a-r1-b` и `a-r2-c`. При весах `1,1` лучший mapping отправляет `c→c`;
при весах `1,1/3` — `c→b`, потому что первое отношение стало важнее.
Исполняемый контрпример есть в
[тесте](../tests/test_factkg_e1_pilot.py).

## Решение и граница вывода

**Текущая однопроходная E1-гипотеза нерабочая:** её метод тождественен B3,
так что она не может дать улучшение Accuracy за счёт весов. Старый
трёхпроходный пилот не дал положительного результата на 7 потенциально
информативных claims. Он не доказывает, что любой способ назначать разные
веса бесполезен на любой выборке. Для такого общего утверждения конечный
пилот без дополнительных предположений вообще не является доказательством.
