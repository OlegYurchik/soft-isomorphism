# H5: дополнение B1 связными путями

Дата фиксации дизайна: 13.11.2026. Ветка задачи #19.

## Наблюдение и гипотеза

На диагностических FactKG dev-20 простой B1 покрывает 19 из 32
размеченных положительных путей, а тот же candidate pool содержит 27 из
32. Это оценка доступного запаса, а не результат H5: gold используется
только после retrieval.

**H5.** При одном candidate pool и лимите 20 троек дополнение B1
семантически релевантными связными путями длиной 2–3 повысит покрытие
размеченных путей и затем Accuracy относительно B1. Если надёжного пути
нет, метод должен вернуть B1 без изменений.

## Зафиксированный алгоритм

Входом служат сохранённые claim, query graph, entity candidates,
candidate pool и B1 из E4-диагностики. Дополнительных вызовов LLM при
retrieval нет.

1. Из entity candidates начинаются простые направленные обходы KG длиной
   2–3. Для каждого реального KG-ребра разрешено прямое и обратное
   прохождение; в evidence сохраняется исходная тройка.
2. Чтобы ограничить поиск, для каждого узла остаются 16 лучших продолжений
   по лексическому пересечению с claim, а для каждого старта — 64 лучших
   частичных пути на глубину.
3. Путь вербализуется целиком и сравнивается со всем claim одним
   зафиксированным `all-MiniLM-L6-v2`. Жёсткого порога для каждого
   отдельного relation name нет.
4. Первые 12 троек B1 сохраняются. Путь допускается, если его cosine не
   ниже медианы cosine отдельных B1-троек. Лучшие полные пути добавляются
   целиком до общего бюджета 20; оставшиеся места заполняются хвостом B1.
5. Контроль `Flat` использует те же тройки из тех же найденных путей, но
   ранжирует их независимо. Так проверяется вклад связности, а не одного
   расширения множества кандидатов.

Параметры `max_hops=3`, `fanout=16`, `beam=64`, `base_keep=12` и
`evidence_budget=20` фиксируются до просмотра результата H5. Этот первый
прогон на ранее изученных dev-20/test-20 является диагностическим.

## Проверка механизма

Основной retrieval-контраст: `H5 − B1` по покрытию размеченных
положительных FactKG paths на dev. Дополнительно измеряются `Flat`, число
claims с изменённым evidence и непустой evidence.

Механизм проходит диагностический gate, если H5:

- повышает path coverage минимум на 5 процентных пунктов;
- меняет evidence минимум у 10% claims;
- превосходит Flat либо даёт отдельные восстановления за счёт полного пути.

Reader запускается только после этого gate. Его настройки и prompt должны
быть одинаковы для B1, Flat и H5; UNKNOWN считается ошибкой. Параметры
нельзя менять по test. После диагностического успеха требуется новый
неиспользованный dev и только затем заранее фиксированные 500 test claims.

## Граница утверждения

Поиск путей сам по себе не является заявлением о новизне. Проверяемый
вклад — использование связного поиска как остаточного дополнения к
лексическому B1 с возвратом к B1 при отсутствии надёжного пути. Прямое
превосходство над SimGRAG до сопоставимого независимого теста не заявляется.

## Диагностический результат

Прогон выполнен на ранее изученных первых 20 FactKG dev claims. Retrieval
не обращался к `Label` или `Evidence`; разметка загружена только фазой
`evaluate`.

| Метод | Покрытые paths | Coverage | Изменено claims относительно B1 |
|---|---:|---:|---:|
| B1 | 19/32 | 59,38% | — |
| Flat | 22/32 | 68,75% | 19/20 |
| H5 | 22/32 | 68,75% | 19/20 |

Оба расширения сохранили все 19 paths B1 и восстановили одни и те же три:
два взаимно обратных двухшаговых ограничения `shipBuilder → leaderName`
для Aleksey Chirikov и одношаговый `network` для Bananaman. Хотя evidence
Flat и H5 различается в 19 claims, нет ни одного размеченного path,
восстановленного только H5.

**Решение:** первые два условия gate выполнены (+9,38 п.п. coverage и
изменение 95% claims), третье не выполнено. Связный отбор H5 не показал
эффекта сверх независимого семантического отбора тех же троек. Поэтому
reader не использовался для решения по H5, а test не запускался. Поздний
exploratory reader H6 технически обработал и вспомогательный arm H5:
Accuracy 10/20, UNKNOWN 7/20. Этот постфактум результат не меняет решения
по структурному gate. Диагностика не подтверждает пользу связности в
текущем алгоритме.

Локальные сырые результаты находятся в игнорируемом Git каталоге
`data/evaluation/h5-dev-20/`.

```bash

  --candidate-file data/evaluation/e4-dev-20/candidate-pools.jsonl \
  --out-dir data/evaluation/h5-dev-20 --split dev
PYTHONPATH=src:scripts python scripts/factkg_h5_experiment.py evaluate \
  --candidate-file data/evaluation/e4-dev-20/candidate-pools.jsonl \
  --out-dir data/evaluation/h5-dev-20 --split dev
```
