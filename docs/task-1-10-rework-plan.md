# План доработок задач #1–#10

Цель пакета — довести подготовительные задачи до проверяемого состояния по критериям GitHub issues и замечаниям руководителя. План не объявляет графовый эксперимент выполненным: его результат появится только после реализации и запуска B1/B2/B3/E1.

## Порядок и результат

1. **#1. Научный статус:** отделить прочитанные полностью работы от предварительно просмотренных, связать наработки с #3 и #8, обновить список открытых вопросов.
2. **#3. Требования к данным:** добавить явную таблицу «вопрос → вход → единица оценки → gold → метрика», обязательные/желательные условия и ресурсный бюджет.
3. **#4. Поиск датасетов:** восстановить журнал поисковых запросов, первичные источники и причины исключения кандидатов.
4. **#5. Сравнение датасетов:** расширить CSV и Markdown до единой схемы из issue, сохранив проверенные значения и явно помечая неизвестные.
5. **#6. Feasibility:** добавить трассировку 10–20 примеров для каждого выбранного набора, команды, ID и оставшиеся блокеры.
6. **#7. Протокол:** зафиксировать решение по FactKG + HotpotQA, границы вывода, бюджет и чек-лист готовности к запуску.
7. **#8. Обзор методов:** дополнить 3–4 подробных разбора по единой схеме и разделить reference, adaptation и reproduction.
8. **#9. Новизна:** записать три проверяемые гипотезы, рекомендовать E1 и условия отказа от заявления о вкладе.
9. **#10. Адаптер:** привести загрузчик к фактическим FactKG pickle и raw-контракту E1; gold не передаётся extractor/matcher, test поддерживается как claim+label.

## Порядок выполнения

Сначала исправляются документы #1–#9 и адаптер #10. После каждой ветки запускаются локальные тесты, а изменения пушатся только в соответствующую ветку задачи. Затем повторно проверяются зависимости #7 → #10 → #11.

## Граница готовности

Подготовительные задачи считаются готовыми, когда их критерии приёмки подтверждены ссылками на файлы, команды и сохранённые результаты. Наличие протокола, адаптера или тестов не считается запуском графового эксперимента.
