# H6: семантическое расширение B1

Дата фиксации: 13.11.2026. Ветка задачи #19.

## Происхождение гипотезы

H6 сформулирована после диагностики H5. На ранее изученных FactKG dev-20
плоское семантическое расширение повысило покрытие размеченных paths с
19/32 до 22/32, а связный отбор H5 не дал дополнительного эффекта.
Поэтому dev-20 остаётся только exploratory выборкой; подтверждение H6 на
ней невозможно.

## Гипотеза

**H6.** При одном candidate pool и лимите 20 троек замена слабого хвоста
лексического B1 на тройки, выбранные по семантическому сходству полной
вербализации тройки со всем claim, повысит Accuracy и не увеличит UNKNOWN.

## Зафиксированный метод

Используется arm `Flat` из H5 без изменения параметров:

- первые 12 троек B1 сохраняются;
- кандидаты берутся из ограниченной 2–3-hop окрестности linked entities;
- каждая тройка оценивается независимо по cosine между всем claim и
  `source relation target` через зафиксированный `all-MiniLM-L6-v2`;
- допускаются тройки из путей, чей общий score не ниже медианы score
  B1-троек;
- лучшие новые тройки заменяют хвост B1 до общего бюджета 20;
- дополнительных вызовов LLM при retrieval нет.

Primary contrast: `H6 − B1`. H5 остаётся диагностической абляцией и не
входит в утверждение H6.

## Последовательность проверки

1. Exploratory reader на уже изученных dev-20. Gate: Accuracy H6 выше B1,
   UNKNOWN H6 не выше B1.
2. При прохождении gate — запуск без изменения параметров на
   неиспользованной FactKG dev выборке. Primary retrieval metric — path
   coverage; end-to-end metrics — Accuracy и UNKNOWN.
3. Только после успеха на новом dev — заранее фиксированные 500 test
   claims и парная оценка разницы Accuracy.

UNKNOWN считается ошибкой. Reader, prompt, модель и evidence budget
одинаковы. Результат dev-20 может остановить H6, но не может подтвердить
её из-за постфактум происхождения гипотезы.

## Exploratory результат

Reader `iairlab/qwen3.8-27b` запущен с одинаковым prompt и temperature 0.

| Метод | Accuracy | UNKNOWN | Path coverage |
|---|---:|---:|---:|
| B1 | 12/20 = 60% | 6/20 | 19/32 |
| H6 | 11/20 = 55% | 7/20 | 22/32 |

Вердикты совпали в 19 из 20 claims. В единственном изменившемся случае
про claim о Liselotte Grschebina правильный `FALSE` B1 сменился на
`UNKNOWN`; случаев, где только H6 дал правильный ответ, нет. Следовательно,
дополнительные три покрытых path не изменили ответы на положительных
claims, а замена хвоста B1 удалила полезный сигнал в одном отрицательном.

**Решение:** H6 в зафиксированной реализации не прошла оба exploratory
условия: Accuracy снизилась на 5 п.п., UNKNOWN вырос на один. Запуск на
неиспользованном dev и test остановлен. Это отклонение текущего правила
замены хвоста B1, а не доказательство бесполезности любого семантического
расширения.

Сырые результаты находятся локально в игнорируемом каталоге
`data/evaluation/h5-dev-20/`: H6 соответствует arm `Flat`.
