# H7: контекстная стоимость и мягкое расширение домена отображения

Дата фиксации: 13.11.2026. Ветка задачи #19.

## Гипотеза

**H7.** Если при мягком сопоставлении сравнивать целые query/KG edges и
разрешить relation-guided добавление KG-соседей в домены узлов, matcher
чаще найдёт исполнимое отображение и реальные evidence, чем текущая
relation-only стоимость B4.

H7 изменяет именно отображение `f: V_query → V_KG ∪ {null}`. B1 остаётся
внешним retrieval baseline и не входит в алгоритм.

## Стоимость отображения

Query edge вербализуется как
`source: <label>; relation: <phrase>; target: <label>`, KG edge — так же
с KG identifiers и relation. Зафиксированный `all-MiniLM-L6-v2` задаёт
контекстную edge distance `1 − cosine`. Для полного отображения:

`C(f) = 0.3 · mean(node_distance) + 0.7 · mean(edge_distance)`.

Node distance остаётся character-trigram distance; отсутствующее KG edge
получает стоимость 1, null node — 0.8. Отображение инъективно и покрывает
не менее 80% query nodes. Прямое и обратное направления KG различаются.

## Мягкое расширение кандидатов

До поиска выполняются два раунда. Для каждого query edge и текущего
кандидата одного конца рассматриваются реальные соседние KG-тройки.
Пять лучших соседей по контекстной edge similarity добавляются в домен
другого query node; домен ограничен 20 KG nodes. Затем beam search
ширины 64 заново ищет top-50 mappings. Gold-разметка недоступна.

## Абляции и gate

- `B4`: прежняя relation-only стоимость и прежние top-50 B3 mappings;
- `C7`: новая контекстная стоимость, исходные entity candidates;
- `H7`: новая стоимость и relation-guided расширение кандидатов;
- `B1`: только внешний ориентир качества retrieval.

Первый запуск на ранее изученных dev-20 диагностический. Механизм проходит
к reader, если H7 одновременно:

- увеличивает positive path coverage относительно B4 минимум на 5 п.п.;
- превосходит C7 по path coverage либо восстанавливает отдельные paths;
- даёт непустые evidence минимум для 10/20 claims;
- меняет mapping относительно C7 минимум для 2/20 claims.

При успехе один и тот же reader сравнивает B4, C7 и H7; B1 приводится как
внешний контроль. Подтверждение возможно только после неизменного запуска
на неиспользованном dev и затем фиксированных 500 test claims.

## Диагностический результат dev-20

| Метод | Непустые evidence | Positive path coverage |
|---|---:|---:|
| B1 | 20/20 | 19/32 |
| B4 | 3/20 | 8/32 |
| C7: только контекстная cost | 6/20 | 18/32 |
| H7: cost + domain expansion | 20/20 | 16/32 |

H7 изменил mapping относительно C7 в 15/20 claims, но не восстановил ни
одного path, отсутствующего у C7, и потерял два path. Поэтому расширение
domain в зафиксированном виде не прошло gate. Контекстная cost C7 выделена
в отдельную H8.
