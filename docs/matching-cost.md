# Стоимость сопоставления E1

Нормативная постановка и входы: [дизайн E1](experiment-design-v2.md), §5.
Код: `src/soft_isomorphism/matching.py`; параметры: `configs/matching.json`.

Полное отображение включает каждый узел запроса, образ — KG ID либо `null`.
Ненулевые образы инъективны; не менее 80% узлов должны быть сопоставлены.
Узел оценивается расстоянием Жаккара по символьным триграммам подписей,
`?` не задаёт семантического ограничения, `null` стоит 0,8.
Для направленного ребра берётся наименьшее расстояние между его отношением
и отношениями реальных KG-рёбер между образами концов. Если такого ребра нет,
стоимость равна 1. Обратное направление не подменяет прямое; дополнительные
KG-рёбра не штрафуются. Для отношений используется Жаккар по токенам.

Итог: `0.3 * средняя стоимость узлов + 0.7 * взвешенная средняя стоимость рёбер`.
Вес ребра E1 — согласие трёх extraction views, от 1/3 до 1; B3 подаёт все веса 1.
При нуле рёбер остаётся только средняя стоимость узлов. `score_mapping_breakdown`
возвращает обе компоненты и число сопоставленных узлов; `score_mapping` — число.
Пока это стоимость **заданного** полного отображения. Поиск лучшего отображения —
отдельная задача #16; вычисленная стоимость ещё не является результатом эксперимента.

Проверены вручную и тестами: прямое совпадение, неверное направление, подмена
отношения, отсутствующее ребро с разными весами, `null`, ограничение инъективности
и минимум покрытия. Semantic path substitution здесь не разрешён: совпадение
по пути иной длины не доказывает эквивалентность утверждения.
