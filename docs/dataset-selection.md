## 1. Схема сравнения

Напоминание исследовательских вопросов из О3:

- **Q1** — когда мягкое структурное сопоставление (soft iso) находит правильные подграфы KG лучше, чем text-only или exact match?
- **Q2** — что делает случай «нетривиальным» (multi-hop, нелинейная структура, поверхностное несоответствие)?

Must-have критерии из О3:
1. Публично скачиваемые данные, открытая лицензия
2. Стабильные URI / числовые ID сущностей и отношений
3. Явная связь документ→KG-ID + уровень утверждений (triplets)
4. Независимый публичный эталон (без проприетарной системы)

## 3. Короткий список для практической проверки (О6)

На основании таблицы выбраны **3 кандидата** для проверки файлов:

### ★★★ 1. GTSQA (приоритет: высший)

**Обоснование:** единственный кандидат с явными ground-truth answer-subgraphs в test-сете и подтверждённой лицензией CC-BY-4.0. Синтетическая природа — достоинство (низкий leakage risk) и ограничение (нет реальных документов). Покрывает Q1 напрямую.

**Что проверить в О6:**
- Реальная hop-глубина subgraph-структур
- Наличие dev-split (или нужен самостоятельный split)
- Версия Wikidata (2015) — достаточна ли для нашей задачи

---

### ★★★ 2. FactKG (приоритет: высший)

**Обоснование:** наиболее близкая к задаче постановка — claim (= "document graph" в упрощении) сопоставляется с KG-подграфом через 5 типов reasoning, явно включая Multi-hop и Negation. DBpedia — стабильные URI. 108k примеров достаточно для статистически значимой оценки.

**Ограничение:** в test-сете нет subgraph — только entity IDs. Для Q1 потребуется доступ к DBpedia SPARQL-endpoint для восстановления подграфов (или использовать только train/dev для основной оценки).

**Что проверить в О6:**
- Доступность DBpedia SPARQL-endpoint и схема троек
- Лицензия файлов (GitHub репо)
- Формат файлов: JSON/CSV, наличие structured subgraph

---

### ★★ 3. Re-DocRED (приоритет: второй)

**Обоснование:** единственный кандидат с реальными многопредложенческими документами, из которых напрямую строится document graph (тройки уже в аннотации). Wikidata QIDs обеспечивают прямую связь с KG. Нетривиальные структуры: cross-sentence, 96 типов отношений.

**Ограничение:** задача RE ≠ задача subgraph retrieval — нужно самостоятельно построить эталон «какой subgraph KG соответствует этому документу» из аннотированных троек.

**Что проверить в О6:**
- Формат аннотации и совместимость с Wikidata
- Лицензия файлов
- Пример: как именно выглядит document graph после парсинга троек

---

## 5. Финальный выбор и обоснование (О7)

> Входы: [О6](dataset-feasibility.md) — подтверждённые лицензии, форматы, ограничения.  
> Статус решения руководителя: **ОЖИДАЕТ РАССМОТРЕНИЯ** (вместе с О9).

### 5.1 Основной датасет — GTSQA

**Выбран потому что:**
- Единственный кандидат с явным ground-truth answer-subgraph в **test**-сете — необходимо для Q1 без дополнительной адаптации
- Лицензия **CC-BY-4.0** подтверждена — нет ограничений для академического использования и публикации производных данных
- Минимальная адаптация: < 1 ч (только создание dev-split)
- 27 типов структур subgraph (поле `graph_isomorphism`) — прямая ось для разбивки по Q2

**Почему не FactKG как основной:**
- Test-сет не содержит поля `graph` — только entity IDs; оценка Q1 на тесте требует дополнительно 2–4 ч SPARQL-запросов к DBpedia
- CC BY-NC-SA 4.0 ограничивает публикацию производных данных

**Почему не Re-DocRED как основной:**
- Задача RE (relation extraction) ≠ subgraph retrieval — эталон «правильный KG-подграф» нужно строить самостоятельно из Wikidata (2–3 ч адаптации)
- Лицензия MIT не подтверждена прямым чтением LICENSE файла

### 5.2 Дополнительный датасет — FactKG (train/dev)

**Роль:** проверка Q2 — разбивка результатов по 5 типам reasoning (One-hop, Conjunction, Existence, Multi-hop, Negation). GTSQA не предоставляет семантической типизации reasoning; FactKG позволяет изолировать вклад структуры по типам.

**Ограничения:**
- Использовать только `train` и `dev` (в тесте нет `graph`)
- Академическое использование допустимо; производные данные нельзя публиковать коммерчески

### 5.3 Резервный датасет — Re-DocRED

**Условие активации:** подтверждение лицензии (прочитать LICENSE файл, < 5 мин) + принятое решение по адаптации.

**Роль при активации:** реальные документы (не синтетика) → проверка переносимости метода на естественный текст.

### 5.4 Исключённые кандидаты шорт-листа

| Датасет | Причина исключения |
|---------|-------------------|
| **KGQAGen-10k** | Лицензия не найдена — нарушает must-have #1 до подтверждения; не блокирует, но требует отдельной проверки |
| **FactNet-MFC** | Размер MFC-subset и уровень разметки неизвестны; слишком много н/д после О6 |
| **2WikiMultiHopQA** | Reasoning paths ≠ subgraph-эталон; высокий leakage risk; полезен только как comparison baseline |
